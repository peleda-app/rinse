# Hostile corpus

Invented messages built to attack the content pipeline. Every implementation of `rinse-mail` runs them through the conformance suite (`rinse_mail::testing::run`), which embeds these files at compile time. All addresses are on `example.com` and `example.org`; IP addresses come from the documentation range `192.0.2.0/24`.

The large and binary files (the multipart bomb, the huge header, the deep nesting, the 8-bit garbage, the images) were produced once by a throwaway script and are kept as plain files; edit them like any other fixture.

For every file and every implementation, the suite checks that the call never panics or hangs, that any error is a typed `ContentError`, that every successful output passes `rinse_doc_model::validate` with the request limits and the returned image ids, that `original_html` passes `rinse_mail::check_sanitized_html`, that images are PNG files named by their BLAKE3 hash and within the pixel limit, that the output fits `max_output_bytes` and survives a postcard round trip, and that the string `XSS-MARKER` (placed inside scripts, styles, frames, templates and similar) never appears anywhere in the output. It repeats all of that with tight document limits, a tiny output limit and an input limit one byte below the file size (which must fail with `InputTooLarge` before parsing), and decodes every listed attachment with `decode_part`.
